# Leaderboard Arena

A tongue-in-cheek leaderboard for AI leaderboards. Run `npm ci` and `npm start`, then visit http://localhost:3000.

## Deploy to Vercel

Set the project's Root Directory to `second-opinion`. The checked-in `vercel.json` selects the Other framework, runs `npm run build`, and publishes `public/` plus the Node functions in `api/`. Clean URLs serve the main rankings at `/`, voting at `/arena`, the About page at `/about`, and references at `/sources`. Do not select the Node.js framework: `app.js` is browser code, and running it as a server causes `FUNCTION_INVOCATION_FAILED`.

Run `npm run build` locally to check the production files. `public/` is generated and should not be committed.

## Ranking claims and starting scores

The arena asks whether the visitor agrees with a particular evaluator's published ordering of two models. A vote changes only that evaluator's Elo-style credibility score; the original model scores remain unchanged. Updates use K=32 against a fixed 1,200 reference. Starting Elo scores are subjective editorial priors, not a measurement of public sentiment, and add no fabricated votes. See [SOURCES.md](SOURCES.md) and `data/catalog.json` for the research, initial ratings, exact model configurations, source metrics, dates, and caveats. The initial 17 evaluation boards contain 42 manually curated claims. This is a snapshot, not an automated live scraper.

The selected Review Desk design is shared across Rankings, Arena, About, and Sources. Rankings has a horizontal bar chart and a compact table view; voting is a separate page. The earlier `/dashboard` and `/review` preview paths redirect to the main rankings. Page HTML is generated by `lib/pages.js`; `about.html` holds the About content. Technical score provenance is available on Sources.

Both Rankings and Arena accept `?category=text`, `?category=speech`, `?category=agents`, and `?category=images`. Missing, `all`, or unknown categories show all boards. Tab changes preserve other URL parameters and fragments, add browser history, and carry the category between Rankings and Arena. Agents now covers speech agents (AA Speech Agent Arena and ServiceNow EVA-Bench); Image Generation covers AA, Arena and DesignArena. Human preference, task success, accuracy and experience remain separate source metrics. The model cards show published sample counts, uncertainty and system architecture where available.

The November 4 catalog retires the earlier coding/tool-use agent claims. Their database records and historical votes are preserved; only current catalog claims remain active. Existing Text and Speech identities, source snapshots and votes are unchanged.

## Matchup selection

Each claim has an editorial `relevance` from 1 to 5: 5 for prominent current cross-model comparisons, 3–4 for other relevant comparisons and specialists, and 1–2 for narrow or historical comparisons. These are curation choices, not measured popularity. Relevance is independent of evaluator Elo and vote outcomes. The catalog currently contains 42 claims across 17 boards; selection never invents model comparisons or source results.

Priority is `relevance × freshness / (1 + claimVotes)^0.75`, where freshness is `0.25 + 0.75 / (1 + sourceAgeDays / 90)`. This favors current, relevant claims with little coverage while allowing less prominent claims to surface as well-covered claims lose priority. Selection randomizes among candidates within 80% of the highest priority to spread visitors across similarly useful questions. Category filters and the browser's completed claims are applied first. Skipping excludes the current question when another eligible question exists.

Shared vote counts and browser history refresh before each next question (after voting, skipping or changing arena categories). Visitors arriving simultaneously may still see the same comparison; there are no exclusive reservations. Server-side uniqueness and signed cookies prevent a browser from contributing twice to the same source snapshot. Local development uses the same selection logic with its own browser history.

## Database and shared voting

Provision Neon Postgres through Vercel Marketplace, then connect `DATABASE_URL` to the deployment environment. Configure a random, server-only `VOTE_SECRET` of at least 32 bytes as a sensitive Vercel environment variable. Use separate database resources and voting secrets for preview and production.

With `DATABASE_URL` configured, the build applies additive, repeatable schema/seed migrations and runs database checks inside a subtransaction that rolls back all fixtures. Rebuilding preserves existing scores and votes. The API stores signed anonymous browser identities and hashed network identifiers, validates ranking IDs on the server, prevents duplicate browser votes for the same ranking snapshot, supports idempotent request retries, and imposes no shared-network vote quota. People on the same office or event Wi-Fi can all vote independently. This is basic anonymous voting protection; clearing cookies can still bypass identity limits. Cookie secrets stay on the server. There is no login or claim that each browser corresponds to one unique person.

Without a database, local development uses a separate browser-local score key. Earlier provider-versus-provider prototype scores are not imported into the new ranking-claim system. When a configured database is unavailable, shared voting reports an error instead of silently switching to local scores.

Run `npm test` for API/catalog checks. The production build additionally runs SQL integration checks whenever `DATABASE_URL` is present. The generated static output contains no database credentials or server source.
